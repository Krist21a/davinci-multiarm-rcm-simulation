> 非解剖测试片的当前 M5 实现、运行入口与停刀门槛见 [M5_ENDPOINT.md](M5_ENDPOINT.md)。下文的解剖路线保留作历史规划；它既不是该仿真任务的先决条件，也没有因此解锁。

## 当前边界

本次交付是 **P1 可复现资产审计准备**，不是 P1 完成，更不是 P4 材料校准或临床验证。
本次未实施 P2–P4，也不宣称这些阶段完成。
新增的配置是待审核的声明式规范，**没有接入现有任务运行器**；审计不会启动 CoppeliaSim、
修改场景、生成组织片或执行切割。已有运动学/演示结果不能直接当作筋膜切割实验。

`config/task/fascia_benchmark.json` 保持 `status: blocked`。没有 validated ROI，故
`world_coordinates`、配准变换和标注证据均为 `null`。不能把前列腺表面外偏若干毫米、
放在剪刀前的 PBD 片或旧 feasibility 采样点，重命名为经过验证的筋膜 ROI。
已有 `prostate_access_feasibility.py`、`validation/feasibility/prostate_access.json` 和
`docs/feasibility_prostate_access.png` 仅作为既存探索性分析，本任务不改写它们。

### 术语和假设必须分开

- **Endopelvic fascia、prostatic fascia、Denonvilliers fascia 不是同一个切割目标**。
  Cornu 2010 [2] 用于三筋膜的解剖区分；本基准拟研究 endopelvic fascia 的显式
  **synthetic proxy**，不能用一个笼统的“前列腺旁筋膜片”替代全部层次。
- Siltari 2021 的筋膜保留随机试验 [3] 说明不能把筋膜切开写成所有术式都必需的步骤。
  这里定义的是可控的研究任务，不是临床必须执行的动作或患者适应证。
- 初始条件为 **预设已暴露**，不声称已经仿真了真实暴露过程。**膀胱仍存在、不删除**，
  是遮挡体和受保护结构；“删除膀胱后可达”的乐观界不能作为基线成功证据。
- 当前只有静态解剖资产；NVB 的分布性 [4] 不支持用一个固定点或固定距离表示患者安全。
  后续可构建的是 **模型风险区**，需说明来源、误差和随牵拉形变的对应关系。
  距离/碰撞指标仅是模型内指标，**不是临床安全阈值**。
- PBD 约束应变不是实测组织力；没有标定过的刚度、切割/撕裂阈值或临床安全距离。

## 可复现资产审计

在仓库根目录运行（Windows PowerShell）：

```powershell
python -B -S scripts/analysis/audit_anatomy_assets.py --asset-dir 'D:\仿真环境\assets\bodyparts3d_v4'
python -B -S -m unittest discover -s scripts/tests -p test_anatomy_assets.py -v
```

脚本和测试只用 Python 标准库；`-S` 禁用 site-packages 验证这一点，`-B` 不写字节码。
无需 numpy、trimesh、模拟器或联网。其他既有构建/测试可能需要 numpy，不能将这里的
测试通过误写成整个仓库回归通过。也可以从其他工作目录用脚本绝对路径运行。

输入均只读：

1. `isa_parts_list_e.txt`：FMA、representation ID、英文名称。
2. `isa_element_parts.txt`：FMA、名称、**全部** element file ID，一对多映射不可只取首项。
3. `isa_BP3D_4.0_obj_99.zip`：直接读 ZIP 成员，不解压、不修改源文件。
4. 本次新增的 `fascia_benchmark.json`：`structures` 的已核 ID、名字/别名和预期元素集。

固定输出为 `validation/safety/anatomy_assets.json`。审计全表而不是只审计目标器官：

- 记录三个原始输入文件、脚本、配置的 SHA256；每个 OBJ 的 SHA256 基于**解压后的原始字节**。
  哈希用于追踪输入版本，不是官方真实性或许可有效性的证明。
- `concepts` 保留 FMA→完整 OBJ 集合和两表名称一致性；`objects` 按 **OBJ basename 去重**。
  共享元素不重复计几何，不按哈希合并不同命名资产；同 basename 的多个 ZIP 成员视为歧义，失败。
- 检查非空 `v`/`f`、有限 xyz、基本顶点索引和至少三点面；报告顶点/面数。
  面数是 OBJ `f` 行数，**不是默认三角形数**。不声称检查了流形、水密、自交、组织真实性或材料。
- `structures` 同时核对已知 ID 和规范化名称，并验证完整元素集。缺失、名字不符、
  映射截断、ZIP 缺项、空/非法网格都不静默通过。复合结构仍列出其每个元素。
- 对没有已核 FMA 的三筋膜与 NVB，在两表中做有词边界的名字/别名搜索；
  找到只标 `review_required`，找不到标 `missing_named_asset`。
  **这只是该版本表中未找到命名资产，不是解剖学上不存在**，也不冒充穷尽同义词的本体检索。
- `summary` 几何合计仅统计校验通过的唯一 OBJ，`errors` 说明未通过项；未被引用的 ZIP OBJ
  单独列出且仍检查。排序稳定，不写时间戳、耗时或绝对资产路径；相同输入/脚本/配置重复运行应字节相同。

退出码：`0` 表示源资产完整性审计通过；`1` 表示输入/映射/网格/写入失败；`2` 是 CLI 参数错误。
已知缺失的三筋膜/NVB 是**基准阻塞项**，不把它们伪装成损坏的 ZIP；
所以可以同时得到 `audit_status: passed` 和总 `status: blocked`。
只有报告中的 `source_asset_integrity` gate 可以由脚本标为通过，其他 gates 不会自动开放，
源配置保持待审核状态。输入错误时尝试覆盖旧成功报告为失败报告；若写入失败应以非零退出码为准。

## 分阶段验收（计划，不代表已完成）

顺序为 **末端 correct + P0 → P1 → P2 → P3 → P4**。可提前收集 P4 数据，
但不得把后阶段计划或既有演示当成前阶段验收。每阶段保存版本/参数/种子/失败记录和审核结论。

| 阶段 | 进入条件与工作 | 可检查的验收证据 | 当前边界 |
|---|---|---|---|
| 末端 correct + P0 | 先确认 roll/pitch/yaw/grip 独立语义、实际读回、双钳口/刀片运动及 RCM；命令拒绝原子性、碰撞回退、推进后再检查联锁、遮挡停止、超切和撤回失败处理 | 独立末端变换测试 + Lua/任务回归 + 当前场景重放；保存输入、拒绝原因与停止/恢复轨迹，成功和故障注入都核对 | 本次不修改控制器、不重新宣称 P0 验收 |
| P1：解剖任务定义与资产 | 上游正确性已审核；审计源资产，明确三筋膜、邻近器官、完整映射、synthetic proxy 与暴露假设 | 哈希/非空网格/名称 ID 审计；经审核的 ROI 来源和标注、单位/坐标系/配准/地标误差；保留膀胱下遮挡及可达性；模型风险区的范围和不确定性；所有必需 gates 有证据 | **本次仅审计准备；ROI、配准、暴露验证和风险区仍 blocked，P1 未完成** |
| P2：切割视觉闭环与可复现基线 | P1 范围明确；从图像估计刀尖、切线、抓点及形变，控制输入与仿真真值隔离；固定初始条件和验收定义 | 真值访问审计/禁止控制器读 tissueNodes；估计误差、漂移/深度噪声/遮挡负向测试；可暂停、恢复或明确失败；固定视野/固定牵拉基线及种子/代码/场景记录 | 尚未接入切割视觉估计；现有 World 依赖真值，不满足 P2 |
| P3：联合策略与风险随动 | P2 基线冻结；实现主动视野与牵拉协同，追踪随形变风险区 | 配对多种子对照、消融和不确定性分析；遮挡、滑脱、张力异常、不可达及风险跟踪丢失测试；风险丢失时保守停止/拒绝 | 只能讨论模型内改进，不是神经保留临床效果 |
| P4：材料/切割校准与外部验证 | 有可授权、可追溯的独立测量；预先确定拟合目标和验证协议 | 力–位移、方向/速率效应、切割/断裂数据；参数辨识与区间；分离拟合/留出验证；灵敏度、网格/时间步收敛；外部数据偏差报告 | **未校准、未完成；当前无可填的实验材料参数** |

`fascia_benchmark.json` 的 gates 逐项指向这些证据；`null` 不是默认安全，`blocked` 不能被
成功审计或单次任务完成覆盖。未来接入运行器须另行实现和测试 gate 拒绝机制，本次没有这一接线。

## 待解决问题：前列腺邻近定位尚不成立（M3 阻塞，2026-11-19）

系统定位是"前列腺邻近组织切割的多臂协同视觉伺服"，但当前所有任务仍在剪刀前方的非解剖组织片上运行，"前列腺邻近"目前**不成立**，只是目标。依据（均为探索性几何分析，不含形变）：

- 保留膀胱：即使计入腕部弯折，8 个前列腺侧方目标无一可三臂到达（`validation/feasibility/prostate_access_wrist.json`）。
- 膀胱牵开为预设条件（刚体平移 0–60 mm，膀胱保留为遮挡体和受保护结构，`validation/feasibility/bladder_retraction.json`）：
  - v1（三臂同一点）选出的穿刺点组合在对接时器械杆互相穿插，不可实现；
  - v2（器械间距 ≥12 mm + 穿刺点 ±2° 摆动）：35 mm 起有间距可行组合，但全部不过摆动检查；
  - v3（按合成代理 ROI 推导的任务动作范围）：25–60 mm 全部不可行，约束瓶颈是剪刀无法走完整段切口范围。
- v2、v3 的判据是在看到前一版结果后修改的，原因已写入结果文件，前一版结果原样保留。

因此 `anatomical_roi_and_registration`、`exposure_with_bladder` 继续 `blocked`。后续可能的方向（均未做）：缩短切口、加入侧向牵开分量、改切割方向（解剖依据会变弱）、形变感知的牵开模型。在这一问题解决前，P2/P3 工作在现有非解剖场景上进行，对外不得称为前列腺邻近或筋膜切割结果。

## 优先研究问题与对照设计

建议优先研究 **联合主动视野/牵拉对照与风险随动**，而不是仅增加一个静态筋膜片或
把“多臂切割成功”作为创新。已有自动镜头研究 [5]，也已有不同入路的前列腺切割/牵拉工作 [6]；
不得在未作具体比较的情况下宣称首创、优于已有方法或已完成实验。

建议配对四组：固定视野+固定牵拉、仅主动视野、仅自适应牵拉、联合视野+牵拉。
在相同解剖/ROI、初始状态、扰动种子和动作/时间预算下，再做静态风险区 vs 随形变风险区消融。
正式实验前冻结种子数/种子列表与统计方案；配置当前保持 `not_run`、种子 `null`，不捏造结果。

共同报告任务成功及失败原因、目标/刀片可见性与遮挡时长、切口偏差/超切、代理应变/撕裂、
模型风险区违规、RCM 偏差、碰撞拒绝和调整开销。不能通过删除膀胱、改变 ROI、放宽安全规则或
只报告成功子集使某组占优。风险区跟踪须说明组织形变对应、估计误差和失效策略；模型内零违规
不等于临床神经安全。P4 之前不把代理应变指标改名为真实组织力。
